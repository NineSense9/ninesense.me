# NineSense 密码直登设计

- 日期：2026-08-01
- 状态：已确认，立即实施
- 范围：当前 HTTP 公网后台的管理员登录与敏感操作重新验证

## 目标

管理员在当前公网入口使用账号密码直接登录，并在同一浏览器保留 30 天服务端会话。由于二维码验证在真实手机验证器上无法完成，生产环境暂时不要求动态码。

## 方案

- 新增 `NINESENSE_MFA_ENABLED` 开关，代码默认 `true`，现有测试和未来 HTTPS 部署仍保持两步验证能力。
- 当前生产环境设为 `false`。密码验证成功后直接创建现有 `admin_sessions` 会话、设置 HttpOnly 且 SameSite=Strict 的 30 天 Cookie，并保留登录限速、CSRF、会话撤销和服务端过期检查。
- 关闭状态下，查看加密联系方式、撤销设备、恢复码管理等敏感路径仍保留“最近重新验证”门槛，但只要求再次输入密码。前端根据会话响应隐藏动态码输入。
- 已失效的 MFA 密钥、挑战和恢复码继续保持撤销状态；不删除两步验证实现，待 HTTPS 接入后可仅通过环境变量恢复。

## 验收

- MFA 关闭时，正确密码直接返回会话与 30 天 Cookie，不创建挑战。
- MFA 关闭时，敏感操作的重新验证接受密码且不需要动态码。
- MFA 开启时，既有二维码与动态码流程保持不变。
- 退出登录、会话撤销、CSRF、数据库备份和公网健康检查保持有效。
