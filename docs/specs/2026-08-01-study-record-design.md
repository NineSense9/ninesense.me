# NineSense 备考记录功能设计

- 日期：2026-08-01
- 状态：产品与视觉方向已确认，等待设计文档复核
- 适用范围：公开备考记录页、现有管理平台、FastAPI API、SQLite 数据库

## 1. 背景与目标

NineSense 需要增加一套长期可维护的备考记录功能。它既用于本人安排和回顾学习过程，也用于家长查看近期学习进度。

功能目标如下：

1. 访客无需账号即可查看公开学习记录，但不能进行任何修改。
2. 只有现有管理员账号可以维护计划、任务、复盘、专注时间和考试节点。
3. 支持高数、408、英语、政治四个固定科目的独立专注计时和统计。
4. 每天根据生效中的周计划模板自动生成计划，生成后允许管理员按真实情况修改。
5. 提供月度专注总览、最近 30 天详细记录和独立考研时间表。
6. 每天的任务、状态、复盘和专注明细长期保存在后台，管理员以后可以按任意历史日期回看。
7. 主页继续保留指向初试第一天的倒计时，并展示最近考试节点的小提示。
8. 公开页在电脑、平板和手机上均可完整阅读，后台计时和当日管理也必须适配手机。

本功能不依赖 ICP 备案状态。备案通过和正式部署属于后续阶段。

## 2. 已确认的产品规则

- 公开入口采用较深路径：首页页脚进入“更多记录”，再进入“备考记录”。
- 公开页面名称使用“备考记录”。
- 页面公开可访问，但设置 `noindex`，不主动进入搜索引擎结果。
- 最近 30 天公开任务、状态、专注记录和复盘；更早数据只公开月度汇总。
- 公开范围限制不删除后台明细；所有历史日期的任务、状态、复盘和专注记录长期保留并可由管理员查看。
- 任务状态包括：计划中、进行中、已完成、未完成、休息、取消。
- 休息和取消不进入完成率；未完成进入完成率分母但不进入分子。
- 未完成任务不会自动顺延到第二天。
- 所有复盘、未完成原因和备注都允许公开展示。
- 月度大盘只展示实际数据，不设置学习时长目标、连续打卡或断签惩罚。
- 计时提供 `25/5`、`50/10` 和自定义时长。
- 开始计时前只选择科目，不要求关联具体任务。
- 同一管理员账号在任意设备上只能存在一个活动计时器。
- 计时状态保存在服务器；关闭页面、锁屏或切换设备后仍继续运行。
- 提前结束时由管理员选择保存实际专注时长或放弃记录。
- 公开页仅显示“正在专注 408”等科目状态，不展示实时分钟数。
- 允许手动补录、修改和删除专注记录，操作必须进入审计日志。
- 手机后台支持计时、今日任务、状态和复盘；复杂周计划和历史管理以电脑为主。
- 计时结束提醒支持可开关的声音、系统通知和手机振动。
- 考研时间表预置常见节点，由管理员维护预计或已确认日期、说明和官方来源链接。
- 真实学习方案不写死在程序中，周计划内容后续继续讨论并通过后台维护。

## 3. 非目标

- 不为家长或其他访客创建账号。
- 不提供访客评论、督促、打卡确认或修改申请。
- 不自动抓取研招网或其他网站的考试日期。
- 不引入新的数据库、登录系统、子域名、独立端口或消息中间件。
- 不增加学习目标、排行榜、积分、等级、连续天数或羞辱式提醒。
- 不在本阶段讨论最终学习科目安排、每日任务内容和政治开始日期。
- 不将现有公开主页整体迁移到 React。

## 4. 角色与权限边界

### 4.1 公开访客

公开访客可以：

- 从“更多记录”进入备考记录页。
- 查看今日计划、最近 30 天记录、月度汇总和考研时间表。
- 查看当前是否正在专注以及正在专注的科目。

公开访客不可以：

- 新增、编辑、删除或改变任何学习数据。
- 开始、暂停、结束或修正计时器。
- 调用任何管理写接口。
- 获取管理员账号、审计元数据或未列入公开白名单的内部字段。

### 4.2 管理员

管理员继续使用现有账号、会话、MFA 和 CSRF 机制。管理员可以：

- 维护周计划模板和生效日期。
- 修改当天任务、状态、说明和复盘。
- 使用专注计时器并管理历史专注记录。
- 维护考试节点和初试倒计时目标。
- 导出学习数据并查看相关审计记录。

所有管理写操作都必须经过现有管理员认证和 CSRF 校验。公开页面没有写接口，也不渲染伪装或隐藏的编辑控件。

## 5. 信息架构与页面路径

### 5.1 公开页面

新增以下静态页面入口：

- `/records/`：更多记录索引页。
- `/records/study/`：备考记录公开页。

`/records/` 当前只展示“备考记录”，以后可以容纳科研、阅读等长期记录。首页顶部主导航不增加学习入口，只在页脚增加“更多记录”。

备考记录页包含四个主视图：

1. **今日计划**：初试倒计时、最近考试节点、当前专注科目、当天任务轨迹、完成情况和公开复盘。
2. **专注总览**：当前月份总专注时间、最近 14 天趋势、四科时长和占比、月份切换。
3. **最近 30 天**：每日任务、任务状态、专注记录、复盘和学习活跃度概览。
4. **考研时间表**：报名、网上确认、准考证、初试等节点及预计/确认状态、说明和官方链接。

公开页由静态 HTML、CSS 和少量 JavaScript 构成，通过只读 API 获取动态数据。现有主页和其他静态页面继续由 Nginx 直接提供；只有备考记录页依赖学习查询 API。

### 5.2 管理后台

现有 React 管理平台增加“学习管理”一级入口，包含：

- **今天**：当前计时器、科目选择、计时预设、今日任务和当天复盘。
- **周计划**：按星期、时段和生效日期维护模板。
- **专注记录**：查看、筛选、补录、修改和删除计时记录。
- **历史记录**：按任意日期或日期范围查看和修正任务、状态、复盘与当天专注明细。
- **考研时间表**：维护考试节点、预计/确认状态和倒计时目标。

手机端优先呈现“今天”和计时操作。周计划、批量历史管理和复杂筛选保持可访问，但以桌面端为主要工作环境。

## 6. 公开页面视觉设计

公开页沿用现有 NineSense 视觉语言：

- 黑色首屏、米白正文、琥珀色强调和少量冷灰辅助色。
- 使用现有点阵和轻微纹理背景，不引入紫色、绿色或深蓝科技模板。
- 采用编辑型长页面和完整宽度分区，避免普通仪表盘式卡片堆叠。
- 首屏左侧为“备考这件事，一天一天记录。”，右侧为大型初试倒计时。
- 首屏下方使用一条状态轨展示当前专注科目、最近节点和更新时间。
- 今日任务使用纵向时间轨；休息节点与学习任务同样清晰，但视觉权重更低。
- 专注总览使用趋势柱形图和四科横向分布，不使用目标进度环。
- 最近 30 天使用轻量热度格和记录列表；颜色深浅只表示实际时长，不表达好坏评价。
- 考研时间表使用深色全宽时间轴，与页面首屏形成呼应。

响应式要求：

- 设计基准宽度为 1440、768、390 和 320 像素。
- 手机端首屏、倒计时、状态轨、任务轨、图表和时间轴依次纵向排列。
- 手机端主视图导航允许横向滚动，但页面本身不得横向溢出。
- 文本、数字、状态和图表标签不得截断或遮挡。
- 所有交互支持键盘焦点和 `prefers-reduced-motion`。

页面输出以下抓取控制：

- HTML `robots` 元标签设置为 `noindex, nofollow`。
- Nginx 或应用响应补充等价的 `X-Robots-Tag`。
- 页面仍可通过直接链接正常访问；`noindex` 不是访问控制。

## 7. 数据模型

### 7.1 科目

专注计时的科目固定为：

- `math`：高数
- `408`：408
- `english`：英语
- `politics`：政治

休息不是计时科目，而是每日任务的一种类型。

### 7.2 周计划模板

`study_schedule_entries` 至少包含：

- ID
- 星期
- 任务类型：学习或休息
- 科目；休息类型为空
- 开始时间和结束时间
- 默认标题和默认说明
- 生效日期和可选失效日期
- 排序
- 启用状态
- 创建、修改时间

模板支持多个生效区间。修改模板只影响尚未生成的日期，不反向改写历史计划。

### 7.3 每日计划与任务

`study_days` 至少包含：

- 日期，按 `Asia/Shanghai` 唯一
- 当天公开复盘
- 来源模板版本或生成标识
- 创建、修改时间

`study_tasks` 至少包含：

- 所属日期
- 任务类型：学习或休息
- 科目；休息类型为空
- 开始时间和结束时间
- 标题和说明
- 状态：`planned`、`in_progress`、`completed`、`incomplete`、`cancelled`
- 排序
- 创建、修改时间

休息任务公开显示为“休息”。取消的学习任务公开显示为“取消”。

### 7.4 专注计时与记录

`focus_timers` 只保存当前活动计时状态，至少包含：

- ID
- 科目
- 阶段：专注或休息
- 预设类型：25/5、50/10 或自定义
- 计划专注秒数和计划休息秒数
- 开始、暂停、恢复、计划结束和实际结束时间
- 累计暂停秒数
- 状态：运行中或暂停
- 开始请求的幂等标识
- 创建、修改时间

数据库必须保证同一时间最多只有一条活动计时器记录。

`focus_sessions` 只保存已经确认的专注历史，至少包含：

- ID 和可选来源计时器 ID
- 科目
- 计划专注秒数
- 开始和结束时间
- 实际有效专注秒数
- 完成类型：正常完成或提前保存
- 来源：实时计时或手动补录
- 修正原因和最后修改时间

来源计时器 ID 在存在时保持唯一，确保到期结算或网络重试不会重复生成历史记录。暂停和休息阶段不计入有效专注时长；已放弃计时器直接删除或归档为审计事件，不进入 `focus_sessions`。

### 7.5 考试节点

`exam_events` 至少包含：

- 节点类型和标题
- 状态：预计或官方确认
- 开始日期和可选结束日期
- 说明
- 官方来源链接
- 是否作为初试倒计时目标
- 排序和启用状态
- 创建、修改时间

系统最多允许一个启用中的倒计时目标。主页和备考记录页共享该目标。

## 8. 每日计划生成规则

每日计划采用按需生成的快照机制：

1. 首次读取上海时区的“今天”时，服务检查该日期是否已有 `study_days`。
2. 不存在时，从当天生效的周计划模板创建记录和任务快照。
3. 生成动作属于系统行为，不代表访客拥有写权限。
4. 当天记录生成后，管理员可以修改任务内容、时间、状态和复盘。
5. 后续模板修改不影响已经生成的日期。
6. 当天没有匹配模板时仍创建空白日期，管理员可以手动新增任务。
7. 未完成任务不会复制到次日，也不会自动改变次日模板。
8. 公开接口查询历史或未来日期时不得自动创建记录；管理员可以显式创建或修改指定日期。

该机制不要求引入后台定时任务，同时保证家长先打开公开页时也能看到当天基础计划。

## 9. 计时器行为

### 9.1 开始与运行

- 开始前必须选择四科之一和计时预设。
- 自定义专注与休息时长均设置合理上下限。
- 开始请求使用幂等标识，避免网络重试创建两个计时器。
- 服务端时间是唯一可信时间，浏览器只负责展示倒计时。
- 页面关闭后，服务端依据开始时间、暂停时间和计划结束时间继续计算。

### 9.2 暂停、结束与恢复

- 管理员可以暂停和恢复，暂停时间不计入专注时长。
- 完整到达计划结束时间后，专注记录自动完成并保存。
- 提前结束时弹出“保存实际时长”与“放弃本次记录”。
- 保存后状态为提前保存；放弃后不进入任何统计。
- 重新登录或切换设备时，后台恢复当前活动阶段。
- 专注结束后可以启动休息阶段；休息不进入统计。

### 9.3 公开状态

- 活动专注阶段公开显示“正在专注 + 科目”。
- 暂停、休息或无活动计时器时不显示正在专注科目。
- 公开页面不返回开始时间、计划结束时间或实时剩余分钟数。
- 查询活动计时器时，服务先处理已经到期但尚未落库完成的记录，再返回状态。

### 9.4 提醒

声音、系统通知和振动由管理页面本地触发，默认可关闭。请求浏览器通知权限前必须由管理员主动操作；不要求访客授权任何权限。

## 10. 统计口径

### 10.1 有效专注时间

有效专注时间只累计：

- 正常完成的专注阶段。
- 提前结束后选择保存的实际专注时间。
- 管理员手动补录且未删除的专注记录。

暂停时间、休息时间、已放弃记录和已删除记录不进入统计。

### 10.2 任务完成率

- 分子：状态为已完成的学习任务数量。
- 分母：状态已经结束为已完成或未完成的学习任务数量。
- 休息任务和已取消学习任务不进入分子或分母。
- 计划中和进行中的任务只展示状态，不提前进入完成率。
- 页面同时展示原始数量，避免百分比掩盖样本过少。

### 10.3 月度与历史

- 月度总览按上海时区的自然月计算。
- 展示总有效专注时间、每日趋势、四科时间和四科占比。
- 当前月份和历史月份使用相同统计口径。
- 最近 30 天公开详细记录；更早日期的公开接口只返回月度聚合，不返回任务和复盘正文。
- 管理接口不受 30 天限制，可以读取任意已保存日期的完整任务、状态、复盘和专注记录。
- 历史明细长期保存在数据库中，不因退出公开展示范围而自动归档、聚合覆盖或删除。

## 11. API 边界

### 11.1 公开只读接口

公开接口只使用 `GET`，至少覆盖：

- 今日摘要和当前公开状态
- 指定日期范围内的最近 30 天记录
- 指定月份的聚合统计
- 考试节点和初试倒计时目标

响应使用显式字段白名单。不得返回内部状态、审计信息、管理员身份、修正原因、幂等标识或计时器精确时间。

### 11.2 管理接口

管理接口覆盖：

- 周计划模板增删改查和生效日期管理
- 每日任务与复盘增删改查
- 计时器开始、暂停、恢复、完成、提前保存和放弃
- 专注记录按任意日期范围查询、补录、修改和删除
- 考试节点增删改查和倒计时目标设置
- JSON 与 CSV 导出

所有管理写接口复用现有会话、MFA、CSRF、权限检查、审计和错误响应格式。

## 12. 缓存、刷新与异常处理

- 公开页面采用短轮询更新当前科目状态，不展示逐秒倒计时。
- 月度统计和最近记录使用短期缓存或 ETag，数据修改后必须及时失效。
- 公开 API 暂时不可用时，页面仍显示完整结构、静态说明和友好错误，不展示伪造的旧状态。
- 重复开始计时返回冲突响应，不覆盖现有活动计时器。
- 对计时状态的修改使用事务和数据库唯一约束处理并发设备请求。
- 管理表单网络失败时保留输入内容，允许安全重试。
- 手动补录、修正和删除必须校验日期、时长、科目和时区边界。
- 服务端日志不得记录会话、CSRF、通知权限、完整复盘正文或不必要的学习详情。

## 13. 审计、备份与导出

以下操作写入现有审计系统：

- 周计划模板创建、修改、停用和删除
- 每日任务、状态和复盘修改
- 计时器异常操作和提前结束
- 专注记录补录、修正和删除
- 考试节点和倒计时目标修改

新增表自动进入现有 SQLite 一致性备份。导出提供：

- 完整 JSON：用于未来迁移和恢复。
- 专注记录 CSV：用于个人统计。
- 每日任务 CSV：用于长期归档。

导出文件不包含管理员凭据、会话、审计内部详情或其他网站隐私数据。

学习历史默认长期保留。系统不得因为记录超过 30 天或跨月而删除、覆盖或只保留聚合结果。只有管理员明确执行删除操作时才移除明细，并保留相应审计记录；数据库备份仍按现有备份保留策略管理。

## 14. 测试策略

### 14.1 单元测试

- 周计划生效区间和星期匹配。
- 每日快照生成、空模板和历史不可变规则。
- 无自动顺延。
- 任务完成率和休息/取消排除规则。
- 上海时区下的日、月边界和夏令时无关行为。
- 专注时长、暂停、提前保存、放弃和手动补录计算。
- 30 天详细范围和历史月份聚合范围。

### 14.2 API 集成测试

- 公开接口只有读取能力，写请求被拒绝或不存在。
- 公开字段白名单不泄露内部和管理员字段。
- 管理写接口必须登录并通过 CSRF。
- 两个设备同时开始计时时只有一个成功。
- 浏览器关闭后重新读取仍能恢复正确计时状态。
- 到期计时器只完成一次，不产生重复专注记录。
- 模板修改不改变已生成历史。
- 补录、修正和删除产生正确审计记录。
- 管理员可以跨月份和跨年份读取完整历史明细。

### 14.3 浏览器与响应式测试

- 1440、768、390 和 320 像素宽度无横向溢出。
- 首屏文字、倒计时、状态轨、任务轨、图表和考试时间轴无截断或遮挡。
- 手机端可以完成登录、开始/暂停/结束计时、修改今日任务和填写复盘。
- 页面刷新、切换视图和月份后保持可用状态。
- 键盘操作、焦点样式和减少动效设置正常。
- 通知未授权、被拒绝和不支持时不影响计时保存。

### 14.4 安全与恢复测试

- 未登录访客无法调用管理接口。
- CSRF、跨域和安全响应头保持现有约束。
- 数据库备份包含学习表并可通过完整性检查。
- 数据导出不包含凭据或其他模块的隐私数据。

## 15. 验收标准

- 首页可以通过“更多记录”两级路径进入备考记录页。
- 公开访客可查看今日、30 天、月度和考试时间表，但没有任何修改能力。
- 管理员可以在电脑和手机上完成核心今日工作流。
- 每天计划能够按生效模板自动生成，并允许手动修改。
- 四科计时互斥、跨页面和跨设备一致，统计口径准确。
- 休息和取消不降低完成率，未完成任务不自动顺延。
- 公开页在手机、平板和电脑上无溢出、截断或重叠。
- 页面视觉与当前 NineSense 主页一致，不呈现为普通后台仪表盘。
- 公开详情限制为最近 30 天，更早数据只展示月度汇总。
- 后台能够查看所有已保存日期的任务、状态、复盘和专注明细，公开范围变化不会删除历史数据。
- 页面设置 `noindex`，但直接链接访问不受影响。
- 学习数据进入现有审计、备份和导出体系。
